# 01. 학교 외관(코드 픽셀아트) 적용 + 교정·층 맵 ┌자 재구성 — Claude Code 프롬프트

새 학교 외관 그림은 이미지 AI가 아니라 **코드로 그린 픽셀아트**(`kiosk/tools/school_art.py`)가 원본입니다.
이 프롬프트는 그 코드를 3-3game 저장소에 넣고, 같은 그림체로 게임 외관·폐허 버전·층 평면을 만든 뒤 교정·1~4층 맵을 ┌자로 다시 짭니다.

1. `플립2 웹앱` 폴더에서 저장소를 받습니다.
   ```
   cd "C:\Users\user\Desktop\개인\개발\플립2 웹앱"
   git clone https://github.com/pse915/3-3game.git
   ```
   그러면 폴더가 이렇게 됩니다.

# 1) 그림체 규칙 — tools/school_art.py 가 학교 외관의 유일한 원본
- 새 외관은 이 스크립트로만 만든다. 이미지 생성 AI·손그림·외부 이미지로 바꾸지 않는다.
- 먼저 그대로 실행해 docs/kiosk/art-v1/ 의 기준 이미지와 같은 결과가 나오는지 확인하고, 이후 수정은 이 모양을 유지한다.
- 지켜야 할 그림체:
  - 코드로 그리는 평면 색 픽셀아트. 안티앨리어싱·블러 없음. 확대는 항상 정수 배율 + nearest.
  - 색은 스크립트 상단 팔레트 상수(BRICK·BRICK_L·BRICK_D·FRAME·GLASS·GLASS_D·COPING·PLINTH·CANOPY·GRANITE·
    STEEL·ROOF·VAULT_*·PINE·HEDGE·TRUNK)만 쓴다. 새 색이 필요하면 상수로 추가한다.
  - 벽돌: 기본색 위에 밝은/어두운 점 디더(각 약 10%). 창 묶음 사이에 밝은 벽돌 기둥 + 오른쪽 1px 그림자.
  - 창: 흰 1px 창틀, 세로 창살 2개(3분할) + 가운데 가로 창살, 위쪽 1px 그늘, 일부 창 커튼, 흰 창턱.
  - 면 밝기: 남쪽 면 1.0, 동쪽 면 0.82~0.86, 지붕 1.0~1.08. 지붕은 회색 + 3m 격자 + COPING 색 테두리.
  - 나무는 층층이 납작한 소나무, 건물 앞 화단은 둥근 직사각형 관목.
  - 시계·시계탑·유리 커튼월·유리 캐노피 없음. 옥상 위로 솟는 것은 꺾임 모서리 계단탑과 실외기뿐.
- 기하 상수(D=18, L1=104, L2=56, FH=3.6, XE, STAIR_Y0/Y1, ARCH_Y0, VAULT)는 기준표 기반 추정치다.
  값을 바꾸면 모든 출력이 함께 바뀌어야 한다(그림마다 따로 손대지 않는다).
- 게임 시점 투영(render_sprite): 화면 X = s·(x − 0.5·y), Y = s·(0.55·y − z), s = 6 px/m.
  x=동, y=남, z=위(미터). 본관 x∈[0,L1], y∈[0,D] / 서쪽 동 x∈[0,D], y∈[D, D+L2].

# 2) 스크립트 정리·확장 (기존 출력 모양은 유지)
- argparse 로 `python tools/school_art.py --out components/rpg_game/assets [--only sprite|ruin|hero|plans|all]`.
  같은 입력이면 항상 같은 그림(seed 고정).
- 출력:
  a) school.png ← render_sprite() 1배 크기(약 856×344, 배경 투명). 기존 school.png 를 쓰는 코드에서
     864×448 같은 크기 가정을 찾아 새 크기에 맞게 고친다. 기존 school-source.png 등 옛 원본은 지우지 않는다.
  b) school-ruin.png ← render_sprite(ruin=True): 같은 형태·크기에 금(어두운 지그재그 선), 덩굴(PINE/HEDGE 점 무리),
     깨진 창(GLASS_D + 검은 조각), 지붕 얼룩, 캐노피 처짐. 엔딩 비교 화면(ending_visual.js 등)에서 크기·위치를 맞춘다.
  c) school-hero.png ← render_hero(), 1920×1080. 사이니지 대기화면용(02에서 사용).
  d) school-footprint.json ← 스프라이트 안에서 월드 원점(0,0,0)의 픽셀 위치, s, KX, KY, 건물 바닥 다각형(월드 m),
     중앙현관 문 위치, 조회대 범위, 계단탑 위치. 교정 맵의 solid 타일·포털을 이 값으로 계산해 그림과 어긋나지 않게 한다.
  e) floor-plan-1~4.png ← 같은 팔레트로 위에서 본 층 평면도(┌자 복도, 실 칸, 계단·EV·화장실 표시, 글자 없음).
     02의 위치 안내 화면 배경으로 쓴다. 3배 확대본(floor-plan-N@3x.png)도 함께.
- 실 배치는 새 파일 data/school_layout.json 한 곳에서 관리한다(층, 구역(본관/서쪽 동), 안쪽/바깥쪽, 순서, 이름,
  카테고리, 폭(칸 수)). 기준표 2장의 층별 표를 그대로 옮긴다. floor-plan, 층 맵, 02의 rooms.json 이 모두 이 파일에서 나온다.
  school_art.py 는 이 파일을 읽어 floor-plan 과 kiosk-plan.json(실 이름 → 층·평면 다각형·문 좌표·복도 노드)을 만든다.
- 4층 서쪽 동 끝(아치 지붕) 구역은 "4층 없음(추정)"으로 두고 data/school_layout.json 에 confirmed:false 로 표시한다.
- assets/manifest.json 의 크기·SHA-256 갱신(tools/asset_manifest.py).

# 3) 교정(외부) 맵 school.json 재구성 (build_world.py / world_v2.py 생성 방식 그대로 수정)
- school-footprint.json 으로 건물 발자국을 ┌자로: 맵 위쪽 동서로 긴 본관, 서쪽 끝에서 남쪽으로 꺾인 서쪽 동.
  school.png 오브젝트 위치와 solid 타일이 정확히 겹쳐야 한다.
- 두 동이 감싸는 안쪽에 운동장(트랙 타원), 운동장 북서쪽 급수대, 동쪽 정문, 북쪽 후문, 남동쪽 목련관(급식실·강당) 별동,
  건물 앞 화단·보도블럭. 새로 그리는 바닥·운동장 타일도 school_art.py 팔레트(모래색 운동장 등)에 맞춘다.
- '중앙현관' 포털은 본관 남쪽(운동장 쪽) 면 현관 위치. 플레이어 스폰은 현관 바로 앞. 현관 옆 조회대는 올라갈 수 있는 오브젝트.
- 기존 '미래마을로' 포털은 정문 쪽으로 옮긴다.

# 4) 1~4층 맵 floor1~4.json 재구성
- data/school_layout.json 으로 각 층을 ┌자 복도로: 본관 복도(동서) + 꺾임 계단 + 서쪽 동 복도(남북).
- 실 순서·안쪽/바깥쪽은 기준표 2장 그대로(서쪽 동은 꺾임부→남쪽 끝, 본관은 꺾임부→동쪽 끝).
- 중앙계단은 중앙현관 바로 북쪽, EV는 중앙계단보다 서쪽 꺾임부 근처, 층마다 같은 좌표.
- 계단·EV 포털로 층 이동, 각 실 문 포털은 room-층-번호 맵으로 연결. 4층 서쪽 끝 구역은 막힌 벽.
- build_world.py 의 floors 목록과 실 이름을 school_layout.json 에서 읽게 바꾸고, 교실 1-1~3-6 도 그 위치에 둔다.
- 기존 스토리/퀘스트/퀴즈가 참조하는 맵 id·좌표가 깨지지 않게 바뀐 id/좌표 매핑 표를 만들어 데이터 쪽을 함께 고친다.
- "학교 방 배치는 실제 배치도 확인 전 임시 구성" 같은 안내 문구는 "실제 배치도 기준"으로 바꾼다.
